# Installed target findings

**Date:** 27 September 2026  
**Method:** Read-only inspection of this Windows 11 x64 installation via `Get-AppxPackage`, package manifests, `Get-StartApps`, running process metadata and Relight's package-family probe. No installed target was closed or restarted.

Two distinct packaged applications are present:

| Start menu name | Package family name | Activation ID | Manifest executable | Observed version |
|---|---|---|---|---|
| ChatGPT | `OpenAI.Codex_2p2nqsd0c76g0` | `OpenAI.Codex_2p2nqsd0c76g0!App` | `app/ChatGPT.exe` | `26.924.2738.0` |
| ChatGPT Classic | `OpenAI.ChatGPT-Desktop_2p2nqsd0c76g0` | `OpenAI.ChatGPT-Desktop_2p2nqsd0c76g0!ChatGPT` | `app/ChatGPT Classic.exe` | `1.2026.190.0` |

The versioned `WindowsApps` paths are installation details, not durable launch identities. Several processes for each application are running. A PID or executable name alone cannot identify one logical instance reliably, and launcher handoff cannot be inferred from this static inspection.

The read-only `PackagedProcessProbe` now calls Windows [`GetPackageFamilyName`](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getpackagefamilyname) on current-session, executable-name candidates opened with limited query rights. It also checks the current user's SID and records PID plus start time. A local run found **12** matching `OpenAI.Codex_2p2nqsd0c76g0` processes and **5** matching `OpenAI.ChatGPT-Desktop_2p2nqsd0c76g0` processes, with no inspection failures. The counts are a point-in-time observation, not a stable process topology. The probe reports all candidates and does not choose a main process, activate an app or authorize recovery. Helper/main-process and handoff rules still require a controlled target-specific spike.

The user selected **ChatGPT only**, package family `OpenAI.Codex_2p2nqsd0c76g0`, as the initial installed-app target. **ChatGPT Classic is excluded**, even if installed or running; it has a different package family and activation ID. The `Codex` text in the selected package family does not make Codex a second target. On this installation, a read-only command-line classification found one current-session `ChatGPT.exe` main candidate without Electron's `--type=` switch and 16 same-package helpers with that switch. The main candidate had a window, but the adapter does not require one because a valid background instance may have no window. `ChatGptPackagedDiscovery` now interprets one main candidate as present, helpers alone as absent, and unreadable or multiple main candidates as unavailable; its identity includes session, package family, PID and start time. The production discovery call identified the current main PID and start time.

A controlled activation of the **already running** package used Windows [`IApplicationActivationManager::ActivateApplication`](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-iapplicationactivationmanager-activateapplication) with `OpenAI.Codex_2p2nqsd0c76g0!App` and no arguments. It returned success, while the PID reported by Windows was not the lasting main PID; the same main process was detected afterward. The `PackagedApplicationLauncher` now uses this activation contract and ignores its returned PID. A second spike through that production launcher and discovery adapter likewise preserved the same logical main identity. A temporary Relight host registered this package, observed it with zero automatic attempts, then removed the profile without changing the main instance. Users can now select this known installed package in the Add dialog, but that WPF path has not been interactively checked. These checks did not close the installed app, prove activation from absence, verify helper survival after main exit, or test whether any job resumes. M0 and M4 target gates therefore remain open. Product requirements continue to distinguish application relaunch from resumed work.

An explicit-only `ChatGptPackagedStopper` is now connected to the host for the selected package. It requires a fresh discovery match and rechecks the selected PID, start time, session and main-process name before graceful close or a separately authorized force close. Tests reject changed, unavailable and forged ChatGPT Classic identities without closing a process. The WPF Stop and pause / Restart now buttons remain disabled for packaged targets until the adapter is exercised against ChatGPT in a disposable session; its actual close behavior, helper handling and relaunch remain unverified.

Generic executable registration now rejects direct `WindowsApps` paths. A packaged app's versioned executable location is not a durable launch identity, and this also prevents selecting ChatGPT Classic through the executable browse, drop or running-process path on this installation. The only supported installed-app choice remains the selected ChatGPT package family; other packaged targets need separately validated adapters.
