# History checkpoint

**Date:** 27 September 2026  
**Scope:** First read-only M7 slice; M7 exit criteria are not met.

The History page now reads Relight-owned JSON Lines files under `%LOCALAPPDATA%\Relight\Logs` without stopping monitoring. It shows the latest 500 matching events with local-time labels, severity, event type, profile, state/attempt summary and expandable UTC/correlation details. Filters cover configured and removed applications with retained events, minimum severity, event type, optional episode ID and three time ranges (24 hours, seven days, all retained). Removed applications are labeled in the filter; their original profile IDs remain selectable after removal. Refresh is explicit; opening History requests a fresh load. The summary scans the full selected application, episode and period independent of the row cap and event-type/severity list filters. It counts observed disappearances, automatic reservations and dispatches, stable automatic recoveries, other stable starts, lockouts, reported monitoring gaps and observed restorations. The original log folder can be opened from the page. Export uses the same filters but scans all matching retained records, independent of the display cap, and writes CSV or readable text to a user-selected local file outside Relight's data directory. A temporary file is flushed before replacing the chosen destination; cancellation leaves an existing destination intact.

Settings now offers a local diagnostic ZIP export to a user-selected location outside Relight's data directory. `diagnostics.json` contains application/OS version data, configuration revision and policy/settings without target identities, launch arguments, working directories or argument selectors, plus logging buffer/drop counts and the event scan's completeness counts. `events.jsonl` contains up to 500 latest retained structured events with process identities removed. The ZIP is written to a temporary file, flushed, then replaces the chosen destination. It does not upload or include raw configuration/state files. Malformed event lines are counted and reported to the user. Adapter-specific diagnostics and a full event-chain export are still pending.

The storage reader accepts only the journal's exact owned filename pattern and skips reparse-point files. It de-duplicates event IDs, reports malformed lines and returns the latest matching records with a total count, so truncation is visible. A vanished file during retention is skipped. Other I/O failures reach the page as an error. Reads run away from the WPF dispatcher and a superseded read is cancelled. The coordinator now emits `MonitoringRestored` when detection becomes reliable again. The summary never infers a crash from disappearance or treats a monitoring gap as confirmed application downtime. It now totals the recorded UTC timestamp span only for complete, unambiguous gap/restoration pairs wholly inside the selected period, grouped by profile and ordered by event time. Open, damaged, out-of-period or ambiguous intervals have unknown duration and are reported separately. Clock changes can skew this timestamp span; it is not a confirmed elapsed duration or target downtime. The expandable event details have an explicit Copy details button; clipboard delivery and layout remain to be checked interactively.
