# History checkpoint

**Date:** 27 September 2026  
**Scope:** First read-only M7 slice; M7 exit criteria are not met.

The History page now reads Relight-owned JSON Lines files under `%LOCALAPPDATA%\Relight\Logs` without stopping monitoring. It shows the latest 500 matching events with local-time labels, severity, event type, profile, state/attempt summary and expandable UTC/correlation details. Filters cover configured and removed applications with retained events, minimum severity, event type, optional episode ID and three time ranges (24 hours, seven days, all retained). Removed applications are labeled in the filter; their original profile IDs remain selectable after removal. Refresh is explicit; opening History requests a fresh load. The summary scans the full selected application, episode and period independent of the row cap and event-type/severity list filters. It counts observed disappearances, automatic reservations and dispatches, stable automatic recoveries, other stable starts, lockouts, reported monitoring gaps and observed restorations. The original log folder can be opened from the page. Export scans all matching retained records, independent of the display cap, and writes CSV or readable text to a user-selected local file outside Relight's data directory. When an episode ID is selected, export includes every retained event for that episode regardless of the row view's profile, severity, kind and time filters. Exported rows omit process identity, which can contain a local path. A temporary file is flushed before replacing the chosen destination; cancellation leaves an existing destination intact.

Settings now offers a local diagnostic ZIP export to a user-selected location outside Relight's data directory. `diagnostics.json` contains application/OS version data, configuration revision and policy/settings without target identities, launch arguments, working directories or argument selectors, plus logging buffer/drop counts, a redacted live target-status snapshot (profile ID, adapter kind, detection/recovery categories and problem flag), and the event scan's counts. Raw adapter reasons and process identities are excluded. `events.jsonl` streams every valid retained event found in the owned log files present when the scan begins, without the dashboard's 500-row limit and with process identities removed. A retention lease prevents those files from being pruned during export; later concurrent journal appends may appear in a subsequent export. The ZIP is written to a temporary file, flushed, then replaces the chosen destination. It does not upload or include raw configuration/state files. Malformed event lines are counted and reported to the user. Complete chains older than the retention window cannot be recovered from this bundle.

The storage reader accepts only the journal's exact owned filename pattern and skips reparse-point files. It de-duplicates event IDs, reports malformed lines and returns the latest matching records with a total count, so truncation is visible. A vanished file during retention is skipped. Other I/O failures reach the page as an error. Reads run away from the WPF dispatcher and a superseded read is cancelled. The coordinator now emits `MonitoringRestored` when detection becomes reliable again. The summary never infers a crash from disappearance or treats a monitoring gap as confirmed application downtime. It totals the recorded UTC timestamp span for complete, unambiguous gap/restoration pairs, grouped by profile and ordered by event time. The span is clipped to the selected period even when one or both events fall outside its boundary. Open, damaged or ambiguous intervals have unknown duration and are reported separately. Clock changes can skew this timestamp span; it is not a confirmed elapsed duration or target downtime. The expandable event details have an explicit Copy details button; clipboard delivery and layout remain to be checked interactively.

Launch exception events now carry a structured failure category and a native Win32/HRESULT code when available. The classifier distinguishes missing executables, invalid launch configuration, permission failures, activation failures, cancellation and unknown failures. Appearance timeout and an observed early exit during automatic stability observation are categorized separately without claiming the application crashed. Executable and selected-ChatGPT discovery now carry typed ambiguity, permission, inspection and shared-configuration-change failures, with the native Win32 code when the adapter has one. A transition into unavailable monitoring records those facts without converting unknown to absence or authorizing launch. History details show a suggested check, CSV/text exports preserve the category, and redacted diagnostic bundles retain the category and native code without exception messages or process paths. Focused tests cover permission denial, missing executable, packaged-probe propagation, unavailable-detection no-dispatch, CSV/text export and bundle redaction. The WPF history details and guidance have not been inspected interactively.

The overnight summary now pairs retained monitoring-gap and restoration events before applying a selected-period boundary. A complete pair crossing either or both edges contributes only its overlap with that period; an open or ambiguous interval still contributes no known span. Controlled tests cover a pair crossing both boundaries, a gap opened before the period with no restoration, profile isolation and out-of-order journal writes. The span remains a difference between recorded UTC timestamps, not proof of elapsed unavailability across sleep or a clock change.

History export now holds a shared filesystem lease while scanning a snapshot of the owned log filenames. Journal retention takes the exclusive side of the same lease and defers deletion during an export without marking logging degraded; the next append retries cleanup. If a snapshotted file disappears through another writer or external action, export fails before replacing the chosen destination. A controlled storage test verifies retention deferral and subsequent cleanup. `pwsh -File scripts/Test-LogRetentionLease.ps1` passed locally: a separate process deferred cleanup while the export lease was held, then a separate exporter waited for an exclusive retention lease to release before replacing its destination. The full Release suite passed **203 tests**. This protects files present when the export snapshot begins; it cannot recover records already removed by retention, detect external removal before that snapshot, or prove completeness of malformed lines.
